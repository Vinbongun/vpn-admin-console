# Проверка новой VPS для Remnawave / Xray

Инструкция рассчитана на чистую VPS с Ubuntu или Debian и запуск от пользователя `root`.

Цель проверки — не смешать результаты разных серверов и оценить:

- реальный публичный IP, ASN и геолокацию;
- репутацию IP и доступность сервисов;
- процессор, память и диск;
- скорость сети в мире и до российских городов;
- пригодность сервера как VPN-ноды.

> Выполняйте тесты **до установки Remnawave, Xray, WARP, WireGuard и других туннелей**. Иначе тест может показать выходной адрес туннеля, а не IP VPS.

## 1. Подключиться к VPS

```bash
ssh root@IP_СЕРВЕРА
```

Сразу проверьте имя машины:

```bash
hostnamectl
```

Если имя стандартное или непонятное, задайте узнаваемое имя. Например:

```bash
hostnamectl set-hostname nl-01
```

Переподключаться после этого необязательно.

## 2. Включить запись всех результатов

Эта команда создаст отдельный файл для текущей VPS. Всё, что дальше появляется в терминале, одновременно будет записываться в него.

```bash
REPORT="/root/vps-test-$(hostname)-$(date +%F_%H-%M-%S).log"
exec > >(tee -a "$REPORT") 2>&1
echo "REPORT=$REPORT"
date -u
hostnamectl
```

Не запускайте тесты нескольких VPS в одном SSH-окне.

## 3. Установить необходимые программы

```bash
apt-get update
DEBIAN_FRONTEND=noninteractive apt-get install -y curl wget ca-certificates jq iperf3 mtr-tiny dnsutils
```

Проверить установку:

```bash
curl --version | head -n 1
iperf3 --version | head -n 1
mtr --version
```

## 4. Зафиксировать систему и реальный IP

```bash
echo "===== SYSTEM AND IP ====="
date -u
hostname
uname -a
cat /etc/os-release
lscpu
free -h
df -hT
ip -br -4 addr
ip -br -6 addr
ip -4 route
printf 'ifconfig.me: '; curl -4fsS https://ifconfig.me; echo
printf 'api.ipify.org: '; curl -4fsS https://api.ipify.org; echo
ip -4 route get 1.1.1.1
```

Адреса от `ifconfig.me`, `ipify` и поле `src` в последней команде должны совпадать. Если они отличаются, остановитесь и проверьте маршрутизацию, WARP, VPN или дополнительные IP.

## 5. Проверить геолокацию, репутацию и сервисы

Основной тест для Remnawave:

```bash
echo "===== REMNAWAVE GEOCHECK ====="
curl -fsSL https://geocheck.ing | sh -s -- -4 --mask
```

Он проверяет согласованность GeoIP-баз, ASN, репутацию, признаки VPN/proxy, маршруты и доступность популярных сервисов.

Для полного отчёта без маскировки IP используйте:

```bash
curl -fsSL https://geocheck.ing | sh -s -- -4 --detail
```

Публично отправляйте только вариант с `--mask`.

### Что считать хорошим результатом

- большинство GeoIP-источников показывает страну размещения VPS;
- Google, Cloudflare и популярные сервисы видят примерно один регион;
- нет признаков Tor, открытого proxy и высокого риска;
- ChatGPT, YouTube и нужные вам сервисы доступны;
- маршрут не отмечен как `detour` или `intercepted` без понятной причины.

## 6. Проверить диск, процессор и международную сеть

YABS запускается один раз при покупке VPS:

```bash
echo "===== YABS ====="
curl -fsSL https://yabs.sh | bash
```

Тест может идти 10–20 минут и потребляет заметный объём трафика. Он проверяет диск через `fio`, сеть через `iperf3` и процессор через Geekbench.

Если тариф имеет маленький лимит трафика, используйте сокращённый сетевой тест:

```bash
curl -fsSL https://yabs.sh | bash -s -- -r
```

Запускайте **либо полный, либо сокращённый вариант**, а не оба подряд.

Ориентиры для обычной VPN-ноды:

| Показатель | Минимально приемлемо | Хорошо |
|---|---:|---:|
| RAM | 1 ГБ | 2 ГБ и более |
| Свободный диск | 5 ГБ | 10 ГБ и более |
| 4K disk total | 2 000 IOPS | 10 000+ IOPS |
| Последовательный disk total | 100 МБ/с | 300+ МБ/с |
| AES-NI | включён | включён |
| Сеть до ближайшей Европы | 300 Мбит/с | 1 Гбит/с и более |

Это ориентиры, а не жёсткие требования. Для Xray важны стабильность сети, отсутствие потерь и производительность одного ядра.

## 7. Проверить скорость до России

```bash
echo "===== RUSSIAN IPERF3 ====="
bash <(wget -qO- https://raw.githubusercontent.com/itdoginfo/russian-iperf3-servers/main/speedtest.sh)
```

Оценивайте одновременно скорость и задержку. Для европейской ноды обычно желательно:

- Москва и Санкт-Петербург: задержка примерно до 60–80 мс;
- скорость в обе стороны: не ниже ожидаемого тарифа пользователя;
- отсутствие огромной разницы между Download и Upload;
- похожий результат при повторном тесте в другое время суток.

Один тест не показывает вечернюю перегрузку. Для VPS, которую планируется оставить, повторите российский iPerf3 вечером через 6–12 часов.

## 8. Проверить маршрут при подозрениях на потери

Это не обязательный бенчмарк. Выполняйте, если скорость скачет или есть потери:

```bash
echo "===== ROUTES ====="
mtr -4 -rwzc 30 1.1.1.1
mtr -4 -rwzc 30 ya.ru
```

Потери на одном промежуточном узле не всегда означают проблему: маршрутизатор может ограничивать ответы ICMP. Реальная проблема — потери, которые продолжаются на последующих узлах и присутствуют на конечном адресе.

## 9. Завершить запись и показать файл

```bash
echo "===== TEST FINISHED ====="
date -u
echo "Saved to: $REPORT"
```

Чтобы вернуть обычный вывод терминала и закрыть процесс записи, завершите SSH-сеанс:

```bash
exit
```

После повторного подключения список отчётов можно посмотреть так:

```bash
ls -lh /root/vps-test-*.log
```

Вывести последний отчёт:

```bash
less "$(ls -1t /root/vps-test-*.log | head -n 1)"
```

Для выхода из `less` нажмите `q`. Это просмотр файла, а не выполнение его содержимого.

## 10. Что прислать для анализа

Пришлите один файл `vps-test-ИМЯ-ДАТА.log`. Перед публикацией проверьте, что в нём нет:

- паролей;
- приватных ключей;
- токенов панели;
- UUID пользователей и готовых VPN-ссылок.

Публичный IP VPS не является секретом, но при желании замените последнюю часть адреса на `*`.

## После установки VPN

Серверные бенчмарки не проверяют, блокируется ли конкретный inbound российскими провайдерами. После создания подключения отдельно протестируйте его из нескольких сетей:

- домашний проводной интернет;
- мобильная сеть хотя бы двух операторов;
- Wi-Fi и мобильный интернет одного телефона;
- обычный режим и вечернее время.

Проверьте открытие сайтов, запуск YouTube, скорость большого скачивания, время подключения и восстановление после переключения Wi-Fi/мобильной сети. Именно этот этап определяет практическую работоспособность VLESS/XHTTP из России.

## Что не требуется запускать каждый раз

- `bench.sh` — в основном дублирует YABS;
- несколько разных IP-quality скриптов — GeoCheck уже объединяет основные проверки;
- обычный Speedtest.net — выбранный сервер нередко даёт случайный или заниженный результат;
- DPI-проверку на зарубежной VPS — она не показывает доступность inbound из российских сетей;
- YABS несколько раз подряд — он нагружает диск, процессор и сеть.

## Короткая последовательность

1. Подключиться и задать понятный hostname.
2. Включить запись в отдельный файл.
3. Установить `curl`, `wget`, `iperf3`, `mtr` и `jq`.
4. Зафиксировать интерфейсы, маршруты и публичный IP.
5. Запустить Remnawave GeoCheck.
6. Один раз запустить YABS.
7. Запустить российский iPerf3 сейчас и повторить вечером.
8. При проблемах использовать `mtr`.
9. После установки inbound проверить подключение из реальных российских сетей.
